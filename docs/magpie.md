# Magpie 本地聚合网关：卡片视图与路由归属

本文件承载 [AGENTS.md](../AGENTS.md) 里「Magpie」小节的完整实现约定。改 `lib/magpie-usage.js`、药丸/弹层的 Magpie 分组与池收窄、或 `ROUTE_USAGE_ID` 的路由归属前先读这里；跨模块铁律与验收纪律仍以 AGENTS.md 为准。

- `LINKED_PROVIDERS.magpie` 的 `via: "magpie"`，由 [magpie-usage.js](lib/magpie-usage.js) 的 `MagpieUsageReader` 在 Host 进程内直取回环 `GET`（默认 `http://127.0.0.1:3425`）。**不进 `CLIENT_FETCH_VIA`**：loopback 免鉴权且页面拿不到宿主进程内连接，与 `/plugins/*` 的 cookie 通道不是一类。`magpie` / `magpie-responses` / `magpie-anthropic` 三条模型路由经 `ROUTE_PROVIDER_ALIAS` 归到 `magpie`。
- **只读**：只发 `GET /v1/magpie/quotas?kept=1`、`/v1/magpie/usage/requests`、`/v1/magpie/concurrency`、`GET /v1/models`；`?kept=0` 会触发全部卡片重查、POST `/refresh` 写提供方侧——都不在主动刷新里使用。读取失败 / 5xx / 非 JSON = 通道缺席（`undefined` → `null`），点名才给安装指引；`data:[]` 是「网关在场但没卡」，不是缺席。缓存 60 秒、有代次保护与 pending 合并，`dispose()` 清理。
- **卡视图**：一张卡 = `linkedAccounts` 一行，`providerGroup`/`providerName` 给分组的键与显示名，`account` =「`name · (alias | user)`」——卡片有 `alias`（掩码账号）用它做显示名，`user` 保留给路由回指；`accountId` 带 `#<idx>` 区隔同 provider 同用户的多套餐；`last:true` → `accountActive`。`used`/`remaining` 是已用百分比写进 `windows[].percent`；窗口名先按已知名归一、再按「读数到重置点的时长」兜底到 5h/day/week/month/period，认不出的不猜；窗口原名写进 `detail.note`，弹层窗口卡片标题**优先显示原名**（「Credits」「Total credits」「通用积分池 · 5 hours」直接写是什么额度），周期档位词只在没有原名时用，说明行不重复原名。**`text:true` 是纯剩余文本窗**（Loomy 永久积分）：`display` 只有一个数、无 limit/已用，`remaining` 是占位值——解析 display 得 `detail.left`，不报占位的 100%。**积分型窗口**（`amount`/`limit`/`unit` 在场，如 SenseNova）同步下 `detail.used`/`limit`/`unit` 与 `detail.left`（剩余量按 `limit×remaining` 回推，上游不给直接数字时不猜）：药丸大数字、`pillText` 与窗口卡片优先报「余 N credits」实际数量，百分比条仍画剩余比例但不再独占显示。**纯余额卡**（无 windows）走顶层 `balance` → `amount` 元素 + `extras` 余额行，`until`（可解析日期）→ note 行，不补造百分比窗口。**`display` "a / b" 兜底**：上游只给文本不给结构化字段时按 a 的角色算剩余量——`amount===a`（amount 恒为已用）或 `a/b` 更偏离 `remaining%` 时 a 是已用、余 b−a（Copilot premium / MiMo / OpenDesign / SenseNova）；`a/b≈remaining%` 时 a 是剩余本身（Loomy）；K/M/B 量纲换算；display 给非数值文本（Copilot「Unlimited」）原样下发 `detail.leftText`（契约字段，客户端当剩余文本显示）。**Antigravity 去重与分池**：上游把每模型的同一额度按「模型×档位」复制下发（Opus/Sonnet/Argon 各 3 档完全相同），另附「池 · 周期」池级名行——同一额度最多出现 4 份。只对 provider=antigravity 按「池+周期+已用%+重置时间」分组去重（未知池保留原名作池身份，不合并两个陌生池）：池级名行退为池名来源不占行（Opus/Sonnet 同池合并成一行「Claude & GPT · 7 days」），模型级行去 (tier) 后缀同名合并（Argon 三档合一），组内无模型行时池级名行自己留下（Gemini · 7 days / 5 hours）。产出 4 窗 3 池：Claude & GPT 周、Gemini 4 Argon 周、Gemini 周 + 5h——池词汇照抄独立通道 `non-gemini`/`gemini`/`gemini-argon` 写进 `groupLabel`，quotas 同步 `poolScope:"independent"`。`readAt` 缺席时窗口档位用 `now` 兜底倒推（`magpieWindowKind` 的时长兜底需要基准）。**模型→池收窄**：`poolForModel` 按 `groupLabel` 池词汇匹配（claude/opus/sonnet/gpt→non-gemini，argon→gemini-argon，gemini→gemini），认不出的模型退回整卡口径不硬配；弹层正文与药丸状态条按收窄后窗口算，路由行加「（池 {名}）」。**模型→渠道卡**：选中模型 id 的 `provider/` 前缀（`kimi/k3.1-pro`→`kimi`）直接匹配 `providerGroup`；`auto/*`、`group/*` 组模型没有 provider 前缀时查快照里 `/v1/models` 的 `owned_by`（先完整 id、后组名后缀）。**自建 `magpie-*` 路由归属**：`settings.magpieRoutes` 的键是路由 provider id（候选来自 `llm.listProviders()`），绑定在场即把该路由解析到 magpie 联动项（不用再配 routeBinding），绑定值做渠道分组；优先于内置别名、不受 `manualMatching` 门控，Client 药丸 `SubusagePillEntry`、`goPanelUsageId`、`resolveRouteTarget` 三处同口径；`modelOwnedBy` 先按路由 id 查绑定，模型 id 前缀查表只是兼容回退。命中顺序：**本会话的**在途 live > 当前模型归组 > **本会话的**上次路由 provider——切换模型立刻切卡，不卡在「上次路由」的用尽横幅；**遥测要先归属再采信**：magpie 的 concurrency / usage 行不区分会话（DSH 不发 `X-Magpie-Session`），只有 `req` 与本会话当前模型一致（去 `auto/`/`group/` 前缀后比较）时才认它——否则切到另一个对话后，别人正在跑的请求会被当成「正在服务」，收窄到别的渠道，本会话模型归不出组时还会一起退回聚合总览。认不出的遥测仍作路由行展示，但标注「其他对话的请求」。账号行「正在服务/上次命中」徽标同样按归属后的 cardId 过滤，不读原始 `routeContext.cardId`。
读数 >24h → `stale`；`error` 卡保留成行不丢。
- **路由口径**：`concurrency.active` 里 `agent==="dsh"` 的在途行（live，正在走的实际上游）压过 `usage/requests` 的最近一次命中（recent），折成 `entry.routeContext`（**模板端口**：字段在场即有路由口径，Client 不查 providerId）。**live 不继承 recent 的 `cardId/account/model/status/at`**：这些字段属于旧请求，concurrency 未报告就缺席；Client 还校验 `cardId` 的 `providerGroup`，拒绝旧 Host/迟到快照的跨渠道回指。**不猜 auto 组上游**：`owned_by` 只是出厂提示，`/v1/magpie/route?session=` 要求 `X-Magpie-Session` 而 DSH 不发；没有日志就说「暂无路由记录」。**药丸只显示当前模型命中的上游卡**：命中顺序为在途 live > 当前模型 `provider/` 前缀（或 `auto/*` 的 `owned_by`）> 上次路由 provider；**遥测先归属再采信**（同上：`req` 与本会话模型对不上就不参与命中卡、不参与池收窄，也不接受它的 `cardId` 回指）；按命中卡判定百分比与状态，不把全部卡的最紧窗当成当前额度。`LinkedAccountList` 按 `providerGroup` 分组平铺、焦点组置顶；有命中卡时只平铺该组（`servingOnly`），其余组收进 `details`（「其他渠道 · G 组 N 张」）；无命中或账号数 >12 也走同一折叠守住 ≤14 行。快照另带 `/v1/models` 的 `{id,owned_by}` 列表供 `auto/*`、`group/*` 归组；它只是当前选择的显示映射，不等于已发生的真实路由。
