# UX 设计（0.13.0，2026-10-13）

本文描述当前实现。核心原则：用量为主，配置不打扰；取数健康与额度状态分开表达。

## 1. Provider 导航

- 固定顺序（取自 Client 的 `PROVIDER_ORDER`）：默认开启的依次为 `Z.ai / Kimi / MiMo / OpenCode Go / Command Code / SuperGrok / MiniMax CN / DeepSeek 账号 / DeepSeek API / ARK Agent Plan / ARK Coding Plan`（Team 两路默认关闭；订阅状态未知时每个已启用的 Ark 分组只显示代表标签）；只展示开启且未被默认隐藏的厂商，按钮导航在窄容器自然换行，全页不使用下拉列表。
- 提供商管理位于底部，通常折叠，无可见条目时自动展开；始终列出全部提供商，采用稳定的单列列表。名称与状态只用于展示，检测开关和「配置 / 收起」是独立按钮；编辑器只在当前项下方展开，不再使用网格跨列或嵌套 Summary。**火山方舟的 4 条路由共用一组 AK/SK，因此合并成一张卡片**；个人版与 Team 各有独立开关，其余 29 条各占一张，共 30 张。
- 新安装有效默认开启 11 条、默认关闭 22 条（含 Codex——它的提供方插件自带用量药丸；火山个人版两条默认开启，Team 两条默认关闭）；检测到凭据或保存凭据**不会**自动开启，已保存的偏好优先。
- 上方仅展示用量；用量选中状态与行内编辑状态独立，浏览其他用量不丢失草稿。编辑器切换仍须先保存或取消；脏草稿仅禁用即时开关，不禁用凭据表单。
- 独立开关立即保存，关闭停止用量请求并隐藏标签/药丸，但保留凭据和模型路由；保存反馈就地显示。
- 「没有检测到API的默认隐藏」默认开启；依据有效来源中 Key / Cookie 是否存在，不依据路由配置、认证或请求成功。未知检测状态不伪装为缺凭据。
- 关闭默认隐藏不会重新开启手工关闭的厂商。隐藏条目仍可主动配置；凭据脏草稿期间锁定即时开关，防止共享 revision 冲突。
- 长厂商名在详情标题显示，provider 技术 ID 收进高级/帮助信息。
- 选中态使用浅色背景与强调边线；状态带图标、文字说明/tooltip，不仅靠颜色。
- 支持键盘方向键、Home/End；尽力记住上次选择，浏览器拒绝存储时不影响功能。

- 顶部不放常驻保存按钮；凭据展开编辑且有修改时显示保存/取消。
- 正常情况下不展示空 Key 表单、长篇说明或重复的厂商技术名称。

- MiMo 主操作为「登录并自动导入」，备用「手动导入」与「清除登录凭据」；OpenDesign 同样提供「登录并自动导入」（遇 Cloudflare 人机验证在弹出窗口中亲自完成，手动粘贴会话 Cookie 为备选）。两家都不提供无效 API Key 输入；官网链接明确仅打开页面。

## 3. 状态：读取、额度、续用与凭据时效分别表达

1. **读取状态**：已获取、加载中、需配置、认证失效、拉取失败、缓存。
2. **额度状态**：充足、偏少、即将用尽、已用尽、受连累、额度未知。
3. **续用条件**：包含额度仍可用、已购余额可按量续用、账户/预算受限、条件未知；不得从百分比单独保证请求成功。
4. **凭据时效**（仅 MiMo）：正常、临近到期、紧急、已过期。

顶部 `X/Y 家数据获取成功` 只描述读取结果，不保证额度可用。厂商导航的图标与说明同时解释读取/额度；例如「Kimi：获取成功；月额度已达限额」（窗口名按账户实际下发的集合，老套餐为 7 天、新套餐为月度）。

凭据时效是第四条独立轴，不能混进额度档位：额度已用尽时药丸仍优先显示额度告警；否则临近到期用 ⚠ 黄、30 分钟内 ⚠ 橙、已过期 ✕ 红，文案直说「Cookie N 后到期 / 已过期，请重新登录」。药丸弹层常驻显示剩余时间与到期时刻；设置页「登录与凭据」显示登录时间与剩余时间。倒计时归零**不**改变凭据可用性，只提示重新登录；没有计时记录（旧版本保存的 Cookie）明确写「未记录登录时间」，不编造倒计时。

部分数据或没有额度窗口不能默认标绿。仅余额可读应明确额度未知。旧数据只能在允许保留的瞬时失败中标为缓存，并显示上次成功时间；凭据删除、变更或认证失效不能冒充当前成功。

失败/错误文案由 Client 按 Host 的 errorCode 本地化（中英双语），Host 原始中文 message 保留在元素 title 作为排障信息；未知错误码与传输层错误显示原文，排障信息不丢失。

### 状态判定规范（computeStatus，0.10.11 起）

药丸、弹层横幅、设置页横幅与标签栏**四处共用同一个 `computeStatus()`** 的结论与颜色，禁止任何一处另写判定（旧的 `tagColor` / `providerIcon` 已因此删除）。分支优先级从高到低：

0.11.2 语义修正：加载/关闭之后先判轮换池容量及明确账户/预算限制，再判带证据的续用建议、能力范围，最后执行下述基础分支。自动轮换池只要有健康/已购余额可续用账户，默认账户错误不代表池不可用；未知读取不宣称全池耗尽。基础额度耗尽但有 PAYG / included / unknown 建议，用黄色信息提示而非全服务红色不可用。AFP 部分能力耗尽显示范围，月总池共享限制仍保留。旧缓存中的续用条件不当作当前保证。待处理排序复用相同判定。

1. `loading` / `disabled`：灰 … / –，不染色。
2. **额度用尽**（最差窗口 rank 4）：红 ✕，标题「额度已用尽」；连坐窗口是唯一 rank4 时标题「暂不可用」、词「受连累」。
3. **Cookie 到期**（仅 MiMo）：2 小时内黄 ⚠、30 分钟内橙 ⚠、已过期红 ✕。`state=error` 时倒计时不盖过失败原因，**已过期例外**（它本身就是「请重新登录」的行动项）。
4. **需配置**（no-key / no-cookie）：蓝 ⚙ + 行动指引——缺凭据不是失败，不画红色。
5. **读取失败**：红 !，失败原因进横幅依据行。
6. **缓存 / 不完整**：黄 ?；过期缓存即使 `state=error` 也叫「缓存数据」（读取失败是原因，用户看到的是上次的数字）。
7. **额度档位**：充足（绿 ✓，不染色、药丸不写字）/ 偏少（黄）/ 即将用尽（橙）。
8. **仅余额**（成功但无窗口）：余额就是唯一信息，不画成充足。药丸直接显示金额与单位，并按自身单位分级染色。

0.12.0 余额显示改进（发布包不等于本机已更新，也不替代真实账号验收）：

- **余额分级配色**：人民币 < 1 元红、1–5 元黄、≥ 5 元灰；美元 < 0.2 红、0.2–1 黄、≥ 1 灰。`credits` 及其它没有跨厂商统一面值的单位只在**已解析的非正余额**时标红，正余额一律灰色——按绝对量分级只会凭空制造价值感。**这些是产品预警阈值，不是汇率换算，也不承诺「还能跑多少次」**；累计花费（`spend` / `*-spend`）是已花金额，不套用余额阈值。
- **纯余额药丸的前置条件收紧**：只有读取成功且数据完整（无窗口）才走纯余额分支；缓存、部分数据与失败仍是降级态，余额只在依据行里补充。有有效套餐窗口时**窗口始终优先**——负余额不抹掉有效套餐，套餐耗尽也不会被钱包盖过；官方明确给出 PAYG / included 续用建议时，该建议独立保留。

0.13.0 调整：余额统一最多两位小数，原始值决定告警；CNY ≥ 5 / USD ≥ 1 用绿色 ✓（仅表示超过低余额预警阈值，不保证可续用），低余额黄 / 红与 !，未知单位中性 ℹ。设置初始化仅取本机元数据，当前提供商按需刷新；Codex 模型目录暂态空选择保留上一条已知路由，明确模型切换立即跟随。

硬规则：

- 档位词只描述还剩多少：**充足 / 偏少 / 即将用尽 / 已用尽 / 受连累**；禁用「偏高」这类没写清主语的词。阈值（已用 71 / 91 / 100%）与内部 `percent` 口径不变。
- 药丸**有窗口必画迷你余量条**（每窗口一根，满 = 100% 剩余，顺序与弹层一致）；行动项通过 short 一个词表达，不牺牲余量信息；只有无窗口（需配置 / 失败 / 仅余额）才退回状态字形。
- 无窗口成功本身不标绿；只有已解析 CNY / USD 余额达到相应预警阈值才标绿（0.13.0 规则）。缺凭据不是失败；显示舍入不参与限流或余额档位判断。
- **余额型条目的收起不依赖模型路由**：`deepseek`、`deepseek-account`、`siliconflow`、`novita`、`hyperbolic`、`deepinfra`、`vercel-ai-gateway` 无条件可查询——官方余额与本机账号余额都独立于推理入口，处于手动模式或已存 Key 的账号照样能查（火山方舟同此口径）。
- 测试约束：状态断言必须用实际渲染产物（如 `remainWord`、百分比数字），不能用可能残留的旧键名；分支矩阵由 `tests/test-compute-status.mjs` 守护，改判定先改矩阵。

## 4. 数字与窗口

- 药丸与详单主数字都回答「还能用多少」（余）。进度条满格 = 100% 剩余，随已用扣减；已达限额为空槽。条是圆角轨道 + 档位色填充（不是系统 progress 控件）。绝对量明细仍写「已用 / 总计」。内部 `percent` 仍是已用百分数（档位、连坐、接口口径不变）。
- 药丸是图形而不是文字：每个窗口一根迷你余量条（顺序同弹层），正常态无文字；仅在偏少 / 即将用尽 / 已用尽 / 需配置 / 失败 / 缓存 / Cookie 到期时追加一个词并整体染色。弹层顶部状态横幅给出整体结论，由 `computeStatus()` 统一判定。档位词只描述余量（充足 / 偏少 / 即将用尽 / 已用尽 / 受连累），不使用「偏高」。
- 横幅依据取最差窗口；同档优先非连坐的根因窗口。
- 额度限流依据原始数值/接口明确状态，显示舍入不参与判断，99.5% 不得提前成为限流。
- 数值明细使用 provider/窗口单位，不统一硬编码 Credits。
- 连坐只在同一约束范围内从较长周期传到较短周期，或由共享 all 范围（月总池）传出；同层窗口不互相连坐。文本周限制不得连坐独立日能力。LiteLLM 多预算各自展示作用域，不能相互覆盖。
- 倒计时本地更新；到重置时间补一次读取，不承诺「已恢复可用」。
- 普通 TTL、强制刷新与额度重置不能绕过限流退避或 Retry-After。
- 弹层右对齐并限制视口宽度，长文本可换行；使用匹配的主题表面与前景色，适配深浅主题。
- Command Code 分开展示月额度剩余与已购/赠送余额；月窗口明示总额来自套餐快照，未知套餐不编造月总额，只显示已报告的余额/窗口；真实订阅端点读取失败才标部分数据；月池耗尽不自动把短窗口标成受阻。
- OpenDesign 的弹层/设置页里两个美元数字按**池子**命名：`monthly-balance`（订阅额度）写「套餐余额」、`balance`（钱包合计 = 订阅 + 充值）写「总额度」。旧文案「月额度剩余 / 余额」把两池并排成两个可比数字，用户读成「谁大谁小、是不是同一份额度」，因此按池子改名（2026-10-22 用户反馈）。通用 provider 的「月额度剩余」不变——Command Code 那条确实是月池。
- Command Code 弹层底部提供「账户」区：自动轮换 / 默认账户 / 各额外账户按钮列表，当前项高亮（● + 使用中），点击即切换提供方插件的 `activeAccount`（与其设置页同一开关），同时药丸与弹层上方的用量同步切换为所选账户的额度；自动轮换时仍显示默认账户（顶层 Key）的用量，弹层在用量窗口上方标注当前账户并说明不跟随实际服务账户。账户列表来自 settings describe，不发起计费请求；提供方插件未运行时整区降级为不可用提示，用量显示不受影响。
- **设置页挂同一个账户区**：Command Code 的用量面板用的是**同一个组件与同一个控制器**（`CommandCodeAccountSwitch`），所以当前账户、高亮、降级文案、失败回读在两处完全一致，不必跳到提供方插件的设置页去切换。折叠标题直接回答「现在是哪一个账户」——固定账户写「账户名 · 使用中」，自动轮换写「自动轮换」（均附选项数量）。切换后设置页把当前账户同步给共享 store，上方面板与药丸一起改看所选账户的额度。

### 0.12.0：轮换池详情

- 账户容量摘要始终可见；逐账户清单默认收起，原生 `details/summary` 入口为“点击查看详情”，支持鼠标及键盘切换。
- 展开列表自身限高 240px 滚动，不随账户数无限增高；点击账户仍可固定使用。
- 受限账户标明具体周期，如“每周额度已用尽”或“每周 / 每月额度已用尽”；连坐优先显示根限额周期，缺少依据时明确周期未知，不说全部额度耗尽。多层文字允许换行；按量续用与未知状态仍独立解释。

## 5. 凭据编辑

- 明确「继承」和「自定义」来源；兼容旧配置的手动兜底。
- 凭据值只写不回填，保持仅为内部默认，不要求用户操作。「更换 / 清除」为按钮，来源继承/自定义也使用按钮；清除先进入待保存状态并提示后果，取消不删除。
- 套餐使用按钮式单选组，provider 使用可换行标签；设置页不存在原生 select/option。提供商控制使用带 aria-checked 的 switch 按钮。
- Command Code 不做本地凭据编辑：只读展示来源（凭据服务 / 环境 / cmd 登录文件），凭据修改指向 设置 → Command Code。
- SuperGrok（`xai-oauth`）不做本地凭据编辑：凭据来源为 Grok / Grok Kit 共享登录文件 `~/.grok/auth.json`，凭据修改指向 设置 → Grok Kit 或 `grok login`；token 过期时本插件经 dsh-grok-kit 官方链静默续约（同一文件同一把锁），续约失败才显示「重新登录」提示；没有继承变量时不展示「继承变量」行。统一用量池按已用百分比展示（剩余 = 100 − 已用）并标注重置时间；套餐名（SuperGrok / X Premium+ 等）与已购加量余额（美元）放弹层 extras，不挤占额度行。
- 自动登录会立即保存，开始前必须先保存或取消当前编辑；期间展示进度和取消，禁用同一家（MiMo / OpenDesign）的手动导入与清除；后台登录任务不禁用其他厂商的凭据编辑。任务状态可跨设置页重开恢复，Cookie 不经过页面回填。
- Cookie 解析失败保留原输入并报错，不在失焦时静默清空。
- 配置保存与在线验证独立反馈；验证失败不把已保存说成未保存。
- 刷新不覆盖未保存编辑；提交带配置 revision，拒绝多窗口过期编辑覆盖。

## 6. 验收边界

自动测试覆盖布局契约、状态和交互逻辑，但打桩 React 不等同真实浏览器视觉验收。正式部署后还应在约 530px 内容区、窄容器、125% 缩放、中文/英文与深浅主题检查导航、弹层和表单。
